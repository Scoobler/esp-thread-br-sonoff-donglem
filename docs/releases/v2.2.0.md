# v2.2.0 — Sonoff Dongle-M OTBR

> **HARDWARE PASS — 2026-11-25.** Tested on Wi-Fi and Ethernet Sonoff Dongle-M units before release.

## Summary

Adds automatic, read-only detection of the Sonoff EFR32MG24 OpenThread RCP UART rate. A single ESP32 host firmware image now supports **115200 baud** (Sonoff OpenThread RCP v2.4.4 configuration) and **460800 baud** (v2.4.5 configuration), without asking users to select a baud rate or replacing the MG24 firmware.

## Changes

- Before OpenThread starts, probe the MG24 at 115200 baud and then 460800 baud. Accept a baud rate only after validating HDLC FCS, Spinel response transaction/property, compatible Spinel protocol 4.3 and a non-empty NCP version.
- Release the probe's UART1 driver before OpenThread initialises its own Spinel UART transport.
- If both rates fail, allow **one additional bounded detection cycle after a 2-second delay** for slow-starting RCPs.
- If neither cycle confirms a compatible OpenThread RCP, keep OpenThread stopped without rebooting or guessing a baud, and flash the Sonoff RGB LED **red continuously (500 ms on / 500 ms off)**.
- Preserve normal Ethernet/Wi-Fi/SoftAP and Thread LED indications on successful detection.
- Preserve the existing Ethernet-first networking and failover policy, Web UI, Thread dataset handling and GPIO mappings.
- Keep MG24 firmware updating, resetting, bootloader control and bundling out of the custom ESP32 host image. No changes to Espressif/OpenThread components or GitHub Actions workflows.

## Prerequisites and installation

1. **Use the official Sonoff Dongle-M firmware first** to configure the onboard EFR32MG24 in **Thread RCP Mode**, not Zigbee coordinator mode.
2. A compatible MG24 OpenThread RCP may communicate at either 115200 or 460800 baud; the ESP32 firmware discovers the working rate automatically.
3. Back up an existing Thread Active Operational Dataset before replacing ESP32 firmware.
4. Flash the merged `sonoff-dongle-m-otbr-v2.2.0.bin` **ESP32 image at offset 0x0** with the supported Sonoff Dongle Flasher or `esptool`. This release does not flash MG24 firmware.
5. Restore the saved dataset if required, reconnect the infrastructure backbone, and verify Thread and Home Assistant operation.

See the [README](../../README.md) for the detailed procedure and LED behaviour.

## Compatibility and scope

This is an ESP32 host release. It does **not** bundle or automatically install RCP firmware. An MG24 left on Zigbee firmware will produce the flashing-red fault indication rather than start OpenThread.

The flashing-red RCP fault indication is distinct from the normal short red pulse indicating a detached or disabled Thread network.

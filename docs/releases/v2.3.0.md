# v2.3.0 — Sonoff Dongle-M OTBR

> **HARDWARE PASS — 2026-11-25.** Validated on physical Sonoff Dongle-M units, including a legacy v2.0.1 upgrade. This document is prepared before merging/tagging; the release and GitHub Pages deployment are not yet published.

## Summary

Introduces the browser-based **Scoobler Dongle-M Web Flasher** and a safe USB upgrade image that preserves the existing ESP32 configuration. The installation flow now offers:

- **Fresh installation:** full ESP32 flash erase, then a complete merged firmware image at `0x0`. Use this when migrating from official Sonoff ESP32 firmware or intentionally resetting the installation.
- **Upgrade:** write a dedicated firmware image at `0x20000` without full-chip erase. This retains NVS (including saved Wi-Fi and Thread settings), OTA selection metadata and PHY calibration. **Upgrade is only for existing Scoobler OpenThread Border Router installations with the compatible partition layout.**

Both methods update the **ESP32 host only**; neither flashes the MG24. Users must configure an OpenThread RCP using the official Sonoff firmware before first installing this project.

## New GitHub Pages Web Flasher

- Responsive browser UI built with esptool-js and the Web Serial API (desktop Chrome or Edge).
- Two explicit modes: Fresh installation and Upgrade, with an acknowledgement checkbox tailored to each operation.
- Choose the latest published release, or supply a trusted custom binary for advanced testing.
- Published release images are hosted on GitHub Pages and checked against their SHA-256 digests before flashing.
- Recognises the original ESP32 (including `Unknown ESP32 (revision 3)` as reported by esptool-js) and rejects unrelated ESP32 variants.
- Pulses ESP32 EN via DTR/RTS after programming, enabling automatic restart without disconnecting USB power.
- Completion messages cover either Ethernet or Wi-Fi and distinguish new setup from reconnecting existing settings.

**Flasher URL (available after the first successful Pages deployment):**
https://scoobler.github.io/esp-thread-br-sonoff-donglem/

The repository's **Settings → Pages** deployment source must be set to **GitHub Actions**. The initial tagged GitHub Pages deployment is a post-release verification item, not a completed hardware test.

## Firmware assets

CI and release builds produce two ESP32 binaries and matching SHA-256 checksum files:

| Asset | Flash address | Purpose |
| --- | --- | --- |
| `sonoff-dongle-m-otbr-v2.3.0.bin` | `0x0` | Full merged image for Fresh installation; use with an explicit full erase |
| `sonoff-dongle-m-otbr-v2.3.0-upgrade.bin` | `0x20000` | Settings-preserving Upgrade image covering both application slots and Web UI |

The upgrade builder reads generated ESP-IDF flash metadata and checks that the Sonoff partition table exactly matches the known layout before packaging. It refuses unexpected layouts, preventing an unsafe upgrade image. Both application slots are updated; this is **not** a rollback-capable OTA mechanism.

## Limits and remaining deployment checks

- No bundled MG24/RCP image or automatic RCP firmware flashing; the Sonoff OpenThread RCP is still installed separately.
- Upgrade is limited to current Scoobler firmware installations using the expected partition layout; do not use it to migrate directly from stock Sonoff ESP32 firmware.
- Always back up the Thread Active Operational Dataset before any flash, even a settings-preserving Upgrade.
- After tagging, verify GitHub Pages deployment, both hosted images and SHA-256 validation. An intentionally invalid hosted digest should be rejected before any flash or erase, but that negative case has **not yet** been hardware/browser tested.
- Home Assistant / Thread RCP baud detection functionality from v2.2.0 remains unchanged.

# v2.0.2

## Summary

This release improves Sonoff Dongle-M Ethernet stability and recovery while
preserving the upstream-based Border Router design. It incorporates Igor
Sweet's original Ethernet startup and recovery work from [PR #8](https://github.com/Scoobler/esp-thread-br-sonoff-donglem/pull/8) for
[#5](https://github.com/Scoobler/esp-thread-br-sonoff-donglem/issues/5), plus
the additional integration fixes described below.

## Dongle-M changes

- Ethernet startup waits up to 8 seconds for link, then up to 15 seconds for
  DHCP. A network observed to be slow is remembered and receives a 30-second
  DHCP wait on later boots.
- Wi-Fi or SoftAP provisioning remains the fallback when Ethernet is not
  usable. Ethernet recovery uses a bounded reboot backoff to avoid repeatedly
  switching away from a working Wi-Fi connection.
- Loss of an Ethernet IPv4 address or link clears stale `ETH_READY` state, so
  fallback and provisioning cannot make an incorrect Ethernet-ready decision.
- Sonoff-documented MG24 metadata now identifies reset as GPIO15 and
  bootloader selection as GPIO12. These are metadata corrections only:
  automatic RCP flashing remains disabled and no MG24 firmware is included in
  the ESP32 release image.
- The earlier Ethernet all-multicast fix from [Igor Sweet's PR #4](https://github.com/Scoobler/esp-thread-br-sonoff-donglem/pull/4) is retained for IPv6
  Border Router traffic.

The recorded checksums identify the separately tested images; this release
does not claim binary reproducibility. The tagged-release workflow builds a
fresh versioned firmware image and checksum, then publishes this document as
the GitHub Release body.

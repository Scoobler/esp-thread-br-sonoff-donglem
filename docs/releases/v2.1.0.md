# v2.1.0 — Sonoff Dongle-M OTBR

## Summary

This release integrates 13 new Espressif `esp-thread-br` commits, updates
the Thread REST v2 API and Web UI, and upgrades the firmware toolchain to
ESP-IDF v5.5.6. It also corrects a Sonoff-specific Web/REST startup race
discovered during hardware testing. **HARDWARE PASS: 2026-11-24.**

- Previous baseline: `29a2345e3f0c61bba9307f3daea5ed0c94388ed3`
- New baseline: `847d04f9211d37f082d660fa1f54944d496fca16`
- [Compare upstream commits](https://github.com/espressif/esp-thread-br/compare/29a2345e3f0c61bba9307f3daea5ed0c94388ed3...847d04f9211d37f082d660fa1f54944d496fca16)

### Changes

- Aligned Thread REST APIs, including a new v2 contract, with ot-br-posix
  0.6.0; refreshed the OpenAPI specification and upstream Web UI.
- Included an upstream REST initialisation deadlock fix and Web UI display
  improvements.
- Incorporated the upstream 4 MB example profile without changing the
  existing 16 MB Sonoff board and partition configuration.
- Built using ESP-IDF v5.5.6.

## Sonoff-specific compatibility and fix

- A race was found in initial v2.1.0 hardware tests: Wi-Fi/Ethernet DHCP
  triggered the new REST worker before OpenThread's instance and lock were
  initialised. The fix registers the unchanged upstream server after ESP-IDF's
  explicit `OPENTHREAD_EVENT_START` and replays the selected backbone's
  already-confirmed IP event.
- This gate is confined to Sonoff board configuration, component
  CMake/Kconfig and `dongle_m_network.c`. No changes to the generic
  `esp_ot_br.c`, `border_router_launch.c` or upstream REST implementation
  were needed for the final correction.
- Preserved Ethernet-first selection, Wi-Fi fallback/provisioning, IPv6
  all-multicast reception, LED behaviour, Thread dataset handling, and
  stock MG24 RCP communication at 115200 baud.
- No automatic MG24 flashing or MG24 image in the ESP32 firmware.
- The only approved workflows remain `build_dongle_m.yml` and
  `check_upstream.yml`; no upstream workflows were imported.
